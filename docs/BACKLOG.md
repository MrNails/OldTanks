## Own libraries and engine direction

Decided by Denys on 2026-11-24 ([plan §6](plans/ENGINES-AND-TANK-GAME.md#6-decisions-of-ot-3-and-the-planned-tasks) has scope, settled answers and open questions). Each task gets its `OT-<n>` when its branch is created; the order is planned, only OT-4 and OT-5 were fixed (both done; OT-5 is merged, OT-4 is open on its branch).

- ~~**OT-4 `CoolEngine.Fonts`:**~~ done on `feature/OT-4`, unmerged (2026-11-27): replaces FreeTypeSharp, and the FreeTypeSharp 3 port in `CoolEngine.GraphicalEngine.Core.Font.Font` is gone with it. Every font format except legacy and language-specific ones, full TrueType and CFF hinting, variable fonts, tests against FreeType and Windows (DirectWrite); the plan questions (colour fonts, variable-font axes, CFF stem hints) are answered ([plan §6](plans/ENGINES-AND-TANK-GAME.md#6-decisions-of-ot-3-and-the-planned-tasks), [FONTS](CoolEngine.Fonts/FONTS.md)). Items it left (found 2026-11-25 to 2026-11-27):
  - **The SVG renderer and loader** (its own ticket; Denys: "move SVG renderer and loader to different ticket"): shapes only, the colour from the game's settings. It also draws SVG glyphs from `CoolEngine.Fonts.FontFace.GetSvgDocument`, which exposes each glyph's document today and draws nothing. That XML is untrusted font data: the renderer must not resolve external entities (fontTools' CVE-2023-45139 was such a defect, reported by the domain review of 2026-11-26).
  - **Shaping:** kerning and ligatures (`kern`, `GPOS`, `GSUB`) are a later task; the library works at glyph level only (Denys: "Glyph level only (Recommended)").
  - **An own auto-hinter is not planned.** A TrueType font with no hinting instructions, which FreeType would auto-hint, renders unhinted with a Warning (Denys, 2026-11-27: "Accept, log a Warning (Recommended)"; an auto-hinter task was turned down).
  - **`avar` version 2** (variations): `NotSupportedException` today.
  - **The `fvar`/`name` pair over-reservation** (nit): each distinct pair of an `fvar` and a `name` table reserves the 64 KiB name-ID bit set against the file's parsed-memory budget as if it were kept, about 66.5 KB per pair, so a collection of very many variable faces with distinct names pays it (WP5 review, 2026-11-27).
- **OT-5 `CoolEngine.Mathematics`:** replaces `OpenTK.Mathematics`. Column vectors, column-major storage, clip depth [0, 1], reversed Z, `float` and `double`, 128-bit SIMD; every math change reviewed at effort `max` by `opus` or `fable`. The library, the move and reversed Z are done and merged into `master` by PR #20 ([MATHEMATICS](CoolEngine.Mathematics/MATHEMATICS.md)). Items it left (found 2026-11-26):
  - **A faster same-bits `Matrix4` inverse.** `Matrix4.Inverted` is about 1.9× OpenTK's SSE inverse when that is inlined. If a profile shows inversion, port OpenTK's lane-wise algorithm to `Vector128` without fused multiply-add, keeping the same-bits promise and the four-path test ([MATHEMATICS §8](CoolEngine.Mathematics/MATHEMATICS.md#8-known-limits)). Not worth doing without a profile: inversions are rare per frame.
  - **A self-relative cross-path test.** `CrossPathTests` compares against golden constants recorded on one machine, so the four-path proof is a manual run ([BUILD §2](BUILD.md#2-build)). A test that runs the hashed loop in child processes under the four settings and compares the hashes with each other would need no golden and would run in `dotnet test`.
  - **Pinning built into the benchmark project.** The acceptance runs pass `--affinity` and `--launchCount 3` by hand ([MATHEMATICS §7](CoolEngine.Mathematics/MATHEMATICS.md#7-benchmarks)); a config in `tests/CoolEngine.Mathematics.Benchmarks` could set both so that an unpinned run cannot be mistaken for a result.
  - **Goldens for the GL-only math.** Seven product sites in the move have no automated guard, because they sit in code that needs a GL context: `CoolEngine.Services.Renderers.TextRenderer` (the billboard and its products), `OldTanks.Windows.MainWindow.DrawNormals` and the texture-transform matrix in `ObjectRenderer<T>`'s per-instance path. Extract each into a pure method and pin it with golden values, with a matrix-relative tolerance (review C, 2026-11-26; the sites were verified numerically against OpenTK instead).
  - ~~**Skip the 3D pass while a fullscreen window is minimised.**~~ Done in OT-16 (`bug/OT-16`, 2026-11-27): `OnRenderFrame` draws nothing while the framebuffer is empty ([RENDERING §5](CoolEngine/Services/Renderers/RENDERING.md#5-the-render-target-and-reversed-z)).
  - **Clear the target's depth with `glClearNamedFramebufferfv`** inside `CoolEngine.GraphicalEngine.Core.RenderTarget`, instead of the global `GL.ClearDepth(0)` set once at load (review D's plan challenge; low).
  - ~~**Move the viewport, the projections, ImGui and the render target to `FramebufferSize` together**~~ Done in OT-16 (`bug/OT-16`, 2026-11-27; [KI-032](KNOWN-ISSUES.md#ki-032-the-viewport-projections-imgui-and-render-target-use-the-windows-outer-size) closed).
  - **Ban `Half` and the Bezier types of OpenTK too.** `BannedSymbols.txt` bans the vectors, matrices, quaternions, boxes and the integer and half vectors; OpenTK's `Half` and its Bezier curve types are not covered yet (review C, 2026-11-26).
- **`CoolEngine.OpenGL`:** a Roslyn source generator over `gl.xml` replaces `OpenTK.Graphics` (62 distinct `GL.*` functions in 18 files).
- **`CoolEngine.Platform`:** a Win32 window, WGL context and input replace `OpenTK.Windowing` and GLFW; one window; gamepads in a later task.
- **An own deflate decoder** for the PNG decoder, with full stream-end and Adler-32 checks (Denys: "Document, backlog it"; [KI-023](KNOWN-ISSUES.md#ki-023-png-decoding-cannot-see-a-zlib-streams-missing-end)); it would also close the same limits of the font library ([KI-037](KNOWN-ISSUES.md#ki-037-svg-gzip-documents-with-bytes-between-the-deflate-end-and-the-trailer-are-not-detected), [KI-038](KNOWN-ISSUES.md#ki-038-a-woff-10-zlib-stream-missing-its-end-marker-and-adler-32-is-accepted)).
